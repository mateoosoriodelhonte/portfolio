# Architecture

This is a deliberately small system. The interesting decisions are about what it refuses to
depend on, at build time and at runtime.

## Principles

1. **Static output, minimal client JavaScript.** Every page is prerendered HTML. The only
   client code is one ~150-line script (`src/scripts/app.ts`) plus two page-scoped scripts
   (work filter, RepoSignal pipeline). There is no client framework — nothing on the site
   needed one, and for a portfolio, performance is evidence.

2. **Claims resolve to data, data resolves to evidence.** Pages don't hard-code project facts;
   they read `src/lib/projects.ts` and `src/lib/site.ts`. Anything that could drift — the
   external PR's state — is fetched from the GitHub API during the build, with a committed
   fallback so the build never depends on GitHub being reachable (`src/lib/github.ts`).

3. **The base path is configuration, not convention.** The site deploys under `/portfolio` on
   GitHub Pages. `astro.config.mjs` reads `PUBLIC_SITE_URL` / `PUBLIC_BASE_PATH`, internal
   links go through `withBase()`, and MDX links are rewritten by a component mapping — so a
   future custom domain is an environment change, not a refactor.

## Rendering and data flow

```text
  src/lib/site.ts ─────────┐          GitHub API (build time)
  src/lib/projects.ts ─────┤                 │  fallback: committed state
  src/content/blog/*.mdx ──┤                 ▼
                           ├──────▶  astro build  ──────▶  dist/ (static HTML,
  src/assets/ (screenshots)│         │                     optimized images,
                           │         │ sharp: responsive   self-hosted fonts,
  Fonts API (downloads ────┘         │ AVIF/WebP variants  committed OG cards)
  Google fonts at build)             ▼
                             GitHub Pages (deploy.yml)
```

- **Images** live in `src/assets/` and go through `astro:assets`/sharp for responsive
  variants. They were sourced once from the projects' public repositories and the App Store
  listing (Mateo's own artifacts) — the site never hotlinks or fetches them at runtime.
- **Fonts** are downloaded at build time by Astro's Fonts API and served same-origin with
  generated fallback metrics; no request ever leaves the site's origin at runtime.
- **Social cards** are generated by `scripts/og.mjs` (headless render of the house design) and
  committed, so deploys don't depend on the generator.

## Client runtime

`src/scripts/app.ts` owns all cross-page behavior, and survives Astro's view transitions by
using event delegation plus `astro:page-load` / `astro:after-swap` hooks:

- theme: resolved before first paint by an inline script; toggle persists to `localStorage`;
  OS preference is followed live until the visitor chooses explicitly
- mobile menu: class toggle on `<html>`, Escape support, closed automatically after navigation
- reveal-on-scroll: one IntersectionObserver; elements above the viewport or at page bottom are
  revealed unconditionally so fast scrolling can never strand hidden content
- the hidden state for reveals exists only inside `@media (prefers-reduced-motion:
no-preference)` — reduced-motion users get a fully static page by construction, not by
  override

## Testing strategy

The Playwright suite (`tests/`) runs against `astro preview` serving the production build on a
dedicated port — what passes is what deploys. Structural checks (routes, headings, status
codes), behavioral checks (menu, theme, filter, reveals), honesty checks (drafts excluded from
production, RSS contents), layout guards (no horizontal overflow at any tested viewport), and
axe-core WCAG 2.1 AA scans on ten pages. CI runs format, types, build, and the full suite on
every push and pull request; deploys happen only from `main`.

## What was considered and rejected

- **A client framework** — nothing here has enough state to justify hydration.
- **Runtime GitHub calls** — the site must not degrade when an API does; build-time with a
  fallback keeps the claim fresh _and_ the page static.
- **A CMS** — content is code-reviewed MDX in the repository, same as everything else.
- **Analytics** — nothing is collected. The footer says so, and it's true.
